GBX PROFESSIONAL SERVICES

Launch runbook

Taking gbxps.com live without touching your email.

Every click, in order, across VentraIP, Cloudflare, Microsoft 365 and Resend. Tick each box as you go. Nothing in stages 1 to 8 changes what visitors or email see; the only moment of change is stage 9, and it is reversible.

Set aside about two hours across two days: an hour of setup on day one, a short switch and checks on day two. Do the switch on a weekday morning so you have the day to watch it.

A few words you will see. DNS is the phone book that turns gbxps.com into an address. A record is one line in that phone book. Nameservers are the company that holds the phone book; today that is VentraIP, and in stage 9 it becomes Cloudflare. TTL is how long the internet is allowed to remember a record before checking again.

Stage 1. Make DNS changes propagate quickly

Where VentraIPTime 5 minutes, then wait at least an hourRisk none
  1. In VIPcontrol click My Services, then Domain Names, then gbxps.com.
  2. Open the DNS section. It is labelled DNS Hosting or Manage DNS depending on the layout. You should see the list you pasted to me, starting with the three A records for play, crm and office.
  3. Find the four A records whose hostname is exactly gbxps.com (values starting 198.). Edit each one and change TTL from 3600 to 300. Save each.
    Expect the list now shows 300 next to those four records.
  4. Find the CNAME for www.gbxps.com (value ext-cust.squarespace.com). Edit it, TTL to 300, save.
  5. Do not edit anything else. The MX, TXT and autodiscover records are your email; leave them exactly as they are.
  6. Wait at least one hour before stage 9. Stages 2 to 8 can be done straight away.

Stage 2. Create the leads database

Where CloudflareTime 10 minutesRisk none

The tools and contact form on the site store every submission in a small database called D1. Without it, submissions still email you (after stage 3) but nothing is kept.

  1. In the Cloudflare dashboard, left menu, click Storage & Databases then D1 SQL Database. (Older layouts: Workers & Pages then the D1 tab.)
  2. Click Create Database. Name: gbx-leads. Location: leave on automatic, or choose Asia-Pacific if offered. Click Create.
    Expect a page for gbx-leads with tabs including Console.
  3. Open the Console tab. Paste the whole of the block below into the query box and click Execute. 
    CREATE TABLE IF NOT EXISTS leads (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  created_at TEXT NOT NULL,
  kind TEXT,
  source TEXT,
  email TEXT,
  name TEXT,
  fields TEXT,
  summary TEXT,
  page TEXT,
  ip TEXT,
  user_agent TEXT
);
CREATE INDEX IF NOT EXISTS idx_leads_created_at ON leads (created_at);
CREATE INDEX IF NOT EXISTS idx_leads_email ON leads (email);
    Expect a success message. The Tables tab now lists a table called leads.
  4. Now connect it to the site. Left menu Workers & Pages, click the project gbx, then Settings.
  5. Find Bindings (older layouts: Functions, then D1 database bindings). Click Add, choose D1 database. Variable name: DB (capitals, exactly). Database: gbx-leads. Save.
  6. Bindings only apply to new deployments. Click the Deployments tab, open the menu (three dots) on the top deployment and choose Retry deployment. Wait for it to finish (about a minute).
If you would rather I create the database and run that block for you, say so. Only steps 4 to 6, the binding, have to be done by you in the dashboard.

Stage 3. Set up email sending from the site

Where Resend, then CloudflareTime 15 minutesRisk none

When someone uses a tool or the contact form, the site emails you the details and emails them their results. Resend is the service that sends those. It is free for the first few thousand emails a month.

  1. Go to resend.com and click Get Started. Sign up with admin@gbxps.com.
  2. Left menu Domains, click Add Domain. Enter gbxps.com. Region: choose the closest offered (Sydney if listed, otherwise any). Click Add.
    Expect a page listing three or four DNS records (types MX and TXT, with names like send, resend._domainkey and _dmarc). Leave this tab open. You will copy these into Cloudflare in stage 6. Do not add them at VentraIP.
  3. Left menu API Keys, click Create API Key. Name: gbx website. Permission: Sending access. Domain: gbxps.com. Click Add.
  4. Copy the key (it starts with re_) into your notes file now. It is shown only once.
  5. Back in Cloudflare: Workers & Pages, project gbx, Settings, Environment variables (sometimes under Variables and Secrets). Make sure you are on Production, not Preview.
  6. Add three variables, one at a time, with Add variable:
    NameValueType
    RESEND_API_KEYthe re_ key from your notesSecret (tick Encrypt)
    MAIL_FROMGBX Professional Services <noreply@gbxps.com>Plain text
    MAIL_TOadmin@gbxps.comPlain text
    Click Save.
  7. Retry the latest deployment again, as in stage 2 step 6, so the site picks up the new variables.
Emails will not actually send until the Resend DNS records are live, which happens in stage 6 and 9. That is expected. Submissions are stored in the database in the meantime.

The email rule. The MX record and the autodiscover CNAME must stay on DNS only (grey cloud). If either shows an orange cloud, click it to turn it grey. Everything else about your email is protected by keeping the values identical, which the table above does.

Stage 6. Strengthen email and add the sending records

Where Microsoft 365, Resend, CloudflareTime 15 minutesRisk none

Two email improvements that Squarespace-era DNS never had, plus the Resend records. All added in the Cloudflare copy of the zone, so nothing is live until stage 9.

  1. In Microsoft 365 admin (admin.microsoft.com), left menu Settings, Domains, click gbxps.com, then the DNS records tab.
  2. Look for two CNAME records named selector1._domainkey and selector2._domainkey. If they are listed, copy their values (they end in onmicrosoft.com) into your notes and skip to step 5.
  3. If they are not listed, go to security.microsoft.com. Left menu Email & collaboration, Policies & rules, Threat policies, Email authentication settings, tab DKIM. Click gbxps.com, then Create DKIM keys.
    Expect a box showing the two CNAME records. Copy both names and values into your notes. Leave "Sign messages" off for now.
  4. In Cloudflare, gbxps.com site, left menu DNS, Records, Add record. Add both DKIM records: type CNAME, name selector1._domainkey, target the value from your notes, proxy DNS only. Repeat for selector2.
  5. Add a DMARC record: type TXT, name _dmarc, content exactly:
    v=DMARC1; p=none; rua=mailto:admin@gbxps.com
    This is a reporting-only setting; it does not block anything.
  6. Back to the Resend tab from stage 3. Add each record it lists into Cloudflare the same way, matching type, name and content exactly. Set every one to DNS only. Resend will show them as "Pending" until stage 9 finishes; that is fine.
  7. Optional, but do it after stage 9 is confirmed working: return to the DKIM screen in step 3 and switch Sign messages for this domain with DKIM signatures on.

Stage 7. Point the website project at your domain

Where CloudflareTime 5 minutesRisk none
  1. Workers & Pages, project gbx, tab Custom domains, click Set up a custom domain.
  2. Enter gbxps.com. Continue. Cloudflare shows the DNS record it will create. Click Activate domain.
    Expect gbxps.com listed with status "Pending" or "Initializing". It goes "Active" after stage 9.
  3. Click Set up a custom domain again. Enter www.gbxps.com. Activate.
  4. Check: gbxps.com site, DNS, Records now contains two CNAME records, one for gbxps.com and one for www, both pointing at gbx-2ov.pages.dev, both with an orange cloud. Those are correct as they are.

Stage 8. Send www visitors to the main address

Where CloudflareTime 5 minutesRisk none
  1. gbxps.com site, left menu Rules, then Redirect Rules (may be under Overview then Create rule, choose Redirect).
  2. Click Create rule. Rule name: www to apex.
  3. Under When incoming requests match, choose Custom filter expression. Field: Hostname. Operator: equals. Value: www.gbxps.com.
  4. Under Then: Type Dynamic. Expression:
    concat("https://gbxps.com", http.request.uri.path)
    Status code 301. Tick Preserve query string.
  5. Click Deploy.

Stage 9. The switch

Where VentraIPTime 5 minutes, then 10 minutes to a few hours to take effectRisk low and reversible: put the old nameservers back and everything returns
Before you do this, confirm stage 1 was at least an hour ago, and re-open Cloudflare DNS Records for gbxps.com and check the MX and autodiscover records are present and grey. That is the whole email safety check.
  1. VIPcontrol, My Services, Domain Names, gbxps.com, then Nameservers (sometimes Manage Nameservers).
  2. Choose Custom nameservers. Replace ns1.nameserver.net.au with the first Cloudflare nameserver from your notes, ns2 with the second, and clear ns3 so only two remain. Save.
    Expect a confirmation. The old DNS records stay at VentraIP as a backup; they are simply no longer consulted.
  3. In Cloudflare, gbxps.com site, Overview, click Check nameservers. Cloudflare also emails you when the site becomes Active. This usually takes under an hour, occasionally longer.

If you ever need to undo it: repeat steps 1 and 2 with ns1, ns2 and ns3.nameserver.net.au. Within the hour everything is back to Squarespace and the old records.

Stage 10. Verify everything

Where your browser and phoneTime 15 minutes, once Cloudflare says Active
  1. Open https://gbxps.com. You should see the new site with a padlock in the address bar. If you still see Squarespace, wait ten minutes and try a private window.
  2. Open https://www.gbxps.com. It should land on gbxps.com without www.
  3. Open https://gbxps.com/sitemap.xml and https://gbxps.com/tools/prompt-optimizer/. Both should load.
  4. From a personal email address (Gmail or similar), send a message to admin@gbxps.com. Confirm it arrives. Reply to it from Outlook and confirm the reply arrives back.
  5. On your phone, remove and re-add the admin@gbxps.com account in Outlook, or add it to a second device. If it sets itself up automatically, autodiscover is working.
  6. Open https://play.gbxps.com, https://crm.gbxps.com and https://office.gbxps.com. Each should behave exactly as before.
  7. Run a tool on the site (the Health Check is quickest) through to the email step, using your own email. Two emails should arrive within a minute: one to you as the visitor, one to admin@gbxps.com. If Resend still shows the domain as Pending, wait an hour and try again.
  8. In Cloudflare, Storage & Databases, D1, gbx-leads, Console, run:
    SELECT id, created_at, kind, source, email FROM leads ORDER BY id DESC LIMIT 5;
    Your test submission should be the top row.
  9. In Resend, Domains, gbxps.com should now show Verified. In Cloudflare Web Analytics, visits start appearing within a few minutes once the token is in the site.

Stage 11. Retire Squarespace

Where SquarespaceTime 5 minutes, two days after stage 10
  1. Wait 48 hours after everything in stage 10 passed. There is no cost to waiting and it rules out anyone still seeing a cached old address.
  2. Log in to Squarespace. Site settings, Domains. If gbxps.com is listed as connected, click it and choose Disconnect. The domain itself stays at VentraIP; this only tells Squarespace to stop expecting it.
  3. Settings, Billing, the site subscription, Cancel subscription. Let it run to the end of the paid period rather than requesting a refund, in case you want to check something old.
  4. Back in VentraIP DNS (still there as a backup record set), nothing needs deleting. Leave it.
